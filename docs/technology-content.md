# Editing technology detail pages

Open **Dashboard → Tech Stack → Edit Category**, then expand **Edit technology detail page**. Save the category to publish changes through the existing `tech_stack` Firestore collection.

The authenticated Tech Stack screen automatically creates starter categories when the database is empty, using the existing admin catalog combined with the public fallback catalog and deduplicating technology aliases. It then initializes existing technology records. Records display immediately after reading; loading and permission failures are shown explicitly, and initialization failures do not hide existing records. Each category is read again inside a Firestore transaction; only missing/blank page fields are filled. Existing text and meaningful lists are retained, and no technology records or list rows are appended by initialization. Deleted categories are skipped. Initialization includes categories without `createdAt`.

Each technology receives `starterVersion: 1`. This makes initialization idempotent and preserves subsequent intentional removals and blank fields. New technologies receive defaults on save, even when their detail editor has not been opened. The existing Add Starter Content button excludes technologies already present and uses deterministic category IDs to avoid duplicate starter categories.

`src/data/technologyDetails.ts` retains the original detailed templates. `src/data/technologyProfiles.ts` supplies technology-specific editorial inputs for every name in both the admin starter catalog and public fallback catalog, plus JavaScript. Aliases map Shopify Plus/Development and React.js to their existing templates without creating records. Unrecognized custom technologies receive an identity-specific editable scaffold; review those descriptions before publication.

Editable fields include the hero, overview, benefit cards, technical features, use cases, delivery steps, FAQs, CTA, and SEO metadata. The existing technology icon remains on its technology record. Admin content is persisted, not just substituted in the public React view. Existing URLs and custom slugs remain unchanged.

Verification: `node --experimental-strip-types --test tests/technology-content.test.mjs` and `node tests/technology-browser.mjs`. Browser tests use local Chrome and an in-memory Firestore mock, never the live database. Live records are initialized when an authorized administrator opens Tech Stack in the updated application. No authenticated administrator session or live data export was used during implementation.

Empty-backend regression: `node tests/technology-empty-browser.mjs` verifies automatic persistence of all 44 deduplicated catalog technologies, populated admin fields, brand icon colors, repeat-seed idempotence, and the editor at mobile/tablet/desktop widths. Catalog metadata is shared through `src/data/technologyCatalog.ts`; icon colors use `src/data/technologyIconColors.ts` in both admin and public listings. An empty database initializes automatically; no Add Starter Content click is needed.
